# spfx-tool — active project

## goal
SPFx room reservation dashboard: presentation layer over existing stack
(SharePoint + Power Apps + Power Automate + Outlook).
Fast room discovery, availability visibility, quick booking shortcuts — reusing all existing logic.

## delivery model
No tenant access — .sppkg only. Client uploads to their tenant.
Loop: build local → send .sppkg → client reports → patch → rebuild → resend.
Minimize iterations: maximize tsc + jest coverage before first send.
Workbench: eliminated (no local, no hosted).

## constraints
- .sppkg delivery only — zero tenant dependency in dev workflow
- Dashboard shows and creates items; Power Platform validates/approves/orchestrates
- Zero duplication of existing logic
- Max 1 query Rooms + 1 query RoomReservations per load — never 1 query per room
- Output: clean .sppkg ready for hand-off

## local verification gates (no tenant required)
  tsc --noEmit                    type safety gate (~80% of integration errors pre-deploy)
  jest                            unit tests: AvailabilityCalculator + MockRoomService
  gulp bundle --ship              production bundle (catches import/tree-shaking issues)
  gulp package-solution --ship    .sppkg generation
  unzip -l *.sppkg                inspect: manifest + assets present
  NOT verifiable locally: SP data load, image resolution, Flow trigger, visual rendering

## architecture
SPFx Dashboard → IDataService → Rooms + RoomReservations + Site Assets
Power Automate remains authoritative. Flow triggers independently on list item creation.

- Runtime: Podman rootless container (localhost/spfx-dev:latest, node:22-bookworm-slim)
- Source: ~/unix-toolkit-tools/spfx-tool/ → deploy: ~/dev/spfx/
- Projects: ~/dev/spfx/projects/<name>/
- Build pipeline: gulp bundle --ship + gulp package-solution --ship → .sppkg
- .sppkg output: projects/<name>/sharepoint/solution/

## PATH setup (canonical)
- bootstrap writes to ~/.zshenv.local (never in versioned dotfiles)
- ~/.zshenv (zsh-setup) sources ~/.zshenv.local at end
- ~/.zshenv.local: machine-local, unversioned, outside all repos

## data models (canonical TypeScript)
IRoom:          title: string | roomCode: string | capacity: number | imageName: string
IReservation:   title: string | room: string | startDateTime: Date | endDateTime: Date | status: string
IAvailabilityState: 'Available' | 'Busy' | 'AvailableSoon'  <- union type, not enum
IDataService:   getRooms(): Promise<IRoom[]> | getReservations(): Promise<IReservation[]>
                createReservation(data): Promise<void>

## availability logic (AvailabilityCalculator — pure TS, no SP dependency)
Filter: Status == 'Approved' only — never block on pending/rejected
Busy:           current time between Start and End of any approved reservation
AvailableSoon:  next approved reservation starts within threshold (default 30min — property pane configurable)
Available:      neither Busy nor AvailableSoon
NOTE: visual guidance only — Power Automate is final authority for conflicts

## asset resolution
URL: {siteUrl}/SiteAssets/rooms/{imageName}
Fallback: {siteUrl}/SiteAssets/rooms/room-placeholder.jpg (always present on tenant)
