# spfx-tool — active project

## goal
SPFx web part development without tenant access.
Develop locally → test in local workbench → build → ship .sppkg to client for upload.

## constraints
- No access to SharePoint tenant — client uploads .sppkg
- Must validate everything via local workbench (https://localhost:4321/temp/workbench.html)
- Output: clean .sppkg ready for hand-off

## architecture
- Runtime: Podman rootless container (localhost/spfx-dev:latest, node:22-bookworm-slim)
- Source: ~/unix-toolkit-tools/spfx-tool/ → deploy: ~/dev/spfx/
- Projects: ~/dev/spfx/projects/<name>/
- Dev server: heft start, port 4321, --network=host
- Build pipeline: hybrid (gulp bundle --ship + gulp package-solution --ship) → .sppkg
- .sppkg output: projects/<name>/sharepoint/solution/

## PATH setup (canonical)
- bootstrap writes to ~/.zshenv.local (never to versioned dotfiles)
- ~/.zshenv (zsh-setup) sources ~/.zshenv.local at bottom
- ~/.zshenv.local is machine-local, not versioned, not in any repo

## SSH tunnel for workbench (Android/remote device)
- Dev server binds to ::1 (IPv6 loopback) — not exposed to LAN by default
- Tunnel from Termux: ssh -L '[::1]:4321:localhost:4321' -p PORT user@IP
  (IP/PORT from: grep '^d0|' ~/unix-toolkit-tools/noemap/state/devices.db)
- Browser on Android cannot reach Termux SSH tunnel — use d0 local browser instead
- OR: configure webpack-dev-server to bind 0.0.0.0 (future improvement)
